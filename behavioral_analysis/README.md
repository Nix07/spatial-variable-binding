# Behavioral Analysis — Table 1 reproduction

Reproduces the **Table 1 behavioral accuracy** of *The Dual Mechanisms of Spatial Reasoning in Vision-Language Models* (arXiv [2603.22278](https://arxiv.org/abs/2603.22278)) on the local cluster.

For each of the 12 cells (3 models × 4 tasks), the runner:
1. Loads the model (Qwen2-VL-7B, Gemma-3-4b-it, or Pixtral-12b) via the shared `analysis_utils.load_model()` wrapper.
2. Generates the task's images (synthetic squares/shapes/objects, or stitched What'sUp composites).
3. Builds a chat-templated prompt of the form `"The <property> of the <entity> to the <direction> of <reference> is "` (Fig. 1 of the paper).
4. Runs a single forward pass per item and compares the top-1 next-token to the target.
5. Reports per-direction and overall accuracy.

## Layout

```
behavioral_analysis/
├── README.md                    — this file
├── src/
│   ├── eval.py                  — top-1 scoring + result accumulator
│   ├── run.py                   — `python -m ... --model X --task Y` CLI
│   └── tasks/
│       ├── squares.py           — 3 colored squares, predict color (P(6,3) × 4 dirs)
│       ├── shapes.py            — 3 (shape,color) entities, predict color (P(6,3) × 4)
│       ├── objects.py           — 3 stickpng object thumbnails, predict object (P(8,3) × 4)
│       └── whatsup.py           — stitched What'sUp composites, predict object
├── scripts/
│   ├── run_cell.sh              — `scripts/run_cell.sh <model> <task>` submits one job
│   └── submit_all.sh            — submits all 12 jobs in parallel
├── results/
│   ├── <model>_<task>_baseline.pkl/.txt   — 12 per-cell artifacts
│   ├── table1_summary.csv                 — produced by `analysis/aggregate.py`
│   └── table1_summary.md
├── figures/
│   └── table1_comparison.png    — produced by `analysis/plot.py`
└── analysis/
    ├── aggregate.py             — pkl/txt → CSV + markdown summary
    └── plot.py                  — CSV → 3×4 bar-pair figure
```

Model loading, the chat-templated prompt builder, the 3-rectangle image
compositor, and the color/direction vocab live one level up at
`shared/` and are shared with `last_token_exp/`.

## Reproduction

Single cell, locally on an H100:
```bash
python -m behavioral_analysis.src.run --model gemma3 --task squares
```

All 12 cells in parallel via SLURM:
```bash
behavioral_analysis/scripts/submit_all.sh
```

Refresh the summary + figure from cached results:
```bash
python behavioral_analysis/analysis/aggregate.py
python behavioral_analysis/analysis/plot.py
```

## What'sUp data

The whatsup task expects `shared/whatsup_images/controlled_images/<obj>_<prep>_<middle>.jpeg` JPEGs. These are part of the What'sUp benchmark — already present in this repo.

Two of the four What'sUp cells (Gemma3 and Qwen) are reported from saved Jupyter cell outputs (`results/{gemma3,qwen2vl}_whatsup_baseline.txt`), not freshly re-run. The aggregator parses the `floor prompt` block (the paper's prompt variant) from those summaries.

## Per-model loading notes

`shared/models.py` wraps `analysis_utils.load_model` and adds two patches required on the cluster's `transformers 4.57.6`:

- **Gemma3** — TL's gemma3 weight converter reads `inner_model.language_model.lm_head`, but transformers 4.55+ moves `lm_head` to the top level (`Gemma3ForConditionalGeneration.lm_head`) and replaces `Gemma3ForCausalLM` with a bare `Gemma3TextModel`. `analysis_utils.load_model` aliases lm_head back onto `language_model` defensively.
- **Pixtral** — the HF processor truncates the joint (text + image) token sequence at ~2k by default, breaking the image-token consistency check when a single image expands to >2k patches. We set `processor.tokenizer.model_max_length` to a million and bump `model.cfg.n_ctx`. TL's rotary cos/sin are still precomputed at the original `cfg.n_ctx≈2048`, so per-task canvas sizes are chosen to keep total seq under that limit.

These patches are inert on transformers ≤4.51 (the "Colab compat" layout the paper code was originally written against).
